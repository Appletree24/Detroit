## 明确收缩的范围

- 模型请求采用非流式，避免首版同时实现增量协议。断流/半个 JSON 不执行工具；流式响应状态机留后续。
- 工具串行执行；不会将未经依赖分析的调用自动并行。`apply_patch` 是带前置 digest 的唯一字面量替换，不是通用 unified diff。
- 只有完整历史策略。估算使用 UTF-8 字节数加协议余量，标记 estimator；它不是实际 tokenizer，也不用于计费。
- 只有基本有界恢复：非法参数交回模型、连续错误停止、相同调用和观测多次重复先提醒后停止。暂不重试 provider 错误；SDK `maxRetries=0`。
- shell 超时、取消或输出溢出会终止进程组，副作用状态为 unknown，后续写工具不执行。外层 Bubblewrap PID namespace 与 `--die-with-parent` 覆盖脱离 shell 进程组的后代；已用后台 heartbeat 验证退出后不再写入。
- 运行状态精简为 running 与明确终态；尚未细分 preparing/collecting。raw stdout 为三帧 ready/accepted/done；OMP 在沙箱内逐步保存有界白名单事件，停止后才采集并验证这些证据。没有产品级实时事件流、idle timeout 或后续用户输入协议；不保证未观测的原生消息或辅助调用完整。
- 每个 Trial 一个 Attempt，不自动重试。`recover` 清理未确认环境，不 resume 待执行 Trial；需要新批次重新实验。
- 只支持 UTF-8 常规文件；不读取 symlink、特殊文件与二进制。产物单文件 1 MiB、总计 8 MiB、最多 2000 项；原始证据单文件 16 MiB、总计 64 MiB、最多 20000 项。采集保留安全的部分文件，显式记录缺失与截断；工作区不完整时保留 `evaluation_error` 并禁止不安全重评分。采集大小检查不能替代运行期工作区总磁盘配额。
- usage 缺失保留未知；OMP 只保留主会话上报用量及去重身份观测下界，不声称包含全部重试、辅助或子代理调用。未接价格表、完整缓存/推理 token 成本拆分、统计推断或 Judge；OMP 驱动已有，但现场保存尚未实现。

## 执行与评测边界

Agent 沙箱只获得初始文件、任务说明、运行 driver 和所需配置。真实 provider 请求不含 reference solution 或隐藏断言。合成变体特意使用已知解，名称、规格与报告都保留 synthetic 标识。

Bubblewrap 创建独立 user/PID/IPC/UTS/mount namespace，映射 uid/gid 1000、丢弃 capabilities、启用 no-new-privileges，并清空继承环境。只读挂载 `/usr`、必要系统库、Bun 单文件与 driver；不挂载宿主 home、项目目录或隐藏答案。根目录只读，agent 工作区和原始证据可写，`/tmp` 是 64 MiB tmpfs。

脚本与 verifier 使用独立 network namespace；真实 OpenAI 变体必须显式设置 `sandbox.network: "host"`，连同其工具共享宿主网络。只为联网沙箱挂载 DNS/CA 配置，不提供目标域名白名单。凭据经 stdin 注入所选 driver；reference 工具环境不继承凭据，OMP provider 则接收明确路由的环境变量，不使用 API key argv。OMP 的同用户进程可读环境风险仍存在，不能承诺工具绝对无法取得凭据；verifier 不接收模型凭据。

`prlimit` 禁止 core dump、限制每文件写入 16 MiB、每进程 256 个文件描述符；外层执行有墙钟期限与输出上限。**没有 cgroup 整组 CPU/内存/PID 限额，也没有工作区总磁盘配额**。因此不能沿用原 Docker 的 1 CPU / 512 MiB / 128 PID 保证。

Verifier 在宿主运行可信断言，仅将候选文件与不含答案的 worker 挂载到新的只读沙箱，worker 只接收入口、函数名和参数。可见测试不参与权威评分。worker 启动后候选崩溃、超时或结果无效属于任务 fail；worker 尚未启动的沙箱/runtime 故障属于 evaluation_error。rootless user namespace 不再依赖 root supervisor/setuid 分权。

这是面向固定、非敌对开发任务的最小评测器。它不证明候选函数没有按输入作弊，也不提供恶意多租户安全保证。driver 与 shell 共享 uid，沙箱内原始轨迹不构成防篡改审计；采集后先验证常规文件与大小，再复制到不挂载的宿主证据目录，digest 用来检测后续不一致。后续真实仓库接入需扩展产物、环境与资源配额契约。

## 证据、失败与重评分

```text
.detroit/
  index.sqlite
  writer.lock                         # 仅 coordinator 存活时存在
  <experiment-id>.cancel
  attempts/<attempt-id>/
    input/workspace/                  # 本次独立公开工作区，退出后采集
    input/driver.js
    input/evidence/                   # 沙箱写入的原始轨迹
    agent.process.json                # 宿主记录 PID/start time/boot ID/状态
    verifier.process.json
    evidence/events.jsonl
    evidence/objects/<sha256>         # 请求、响应、工具输出、产物对象
    artifacts.json
    verification/                     # 独立验证 staging
```

冻结的实验保存 Case 内容、seed、请求预算、完整 variant、sandbox 配置、Bun/Bubblewrap/prlimit 二进制 hash、内核/架构、OS 和包清单指纹、driver/verifier digest。参考 Harness 的版本、系统提示及上下文策略只在纯 reference 批次中作为全局配置；包含 OMP 时这些全局字段为未知，实际可观察配置另记证据。宿主工具可能变化，指纹不是完整不可变 rootfs。token 已知小计与 usageComplete 分开。报告成功分子以清理确认后的独立验收结论为准，不因超时或预算停止暗中判失败；未执行、清理未确认、未评分或评分器故障显示 provisional。

对象先写临时文件并 fsync，再 rename，之后追加并 fsync journal。尚未实现目录 fsync、原子 manifest 发布与完整 DB/对象对账，不能宣称掉电零丢失。journal 断尾或对象 hash 错误会显式报错。

评分身份同时包含 worker bundle、宿主断言源码和实际环境指纹。worker 变更后 build，再运行 `score`；代码或环境改变会新增评分版本，并在事件中记录当前环境。相同有效评分幂等；evaluation_error 可重试并保留历史。静态比较报告固定选择原实验冻结的评分版本，优先同版本最后一份有效评分，缺少该版本时保留未评分，不回退到另一个版本；后续重评分在状态和证据中保留。重评分不触发 agent；费用与 usage 仍归属于原始 Attempt。

如果 agent 或 verifier 回收未确认，Attempt 保留已观测的模型结果，cleanup 标为 pending，不冻结仍可能被写入的产物，并停止继续派发。执行停止原因与采集问题分开记录；坏 journal 或超限文件不抹掉原执行结果。`recover` 核对 PID、启动时间和 boot ID，确认 agent/verifier 已退出后解除清理状态。启动记录不完整或身份记录损坏时不猜测 PID，也不会静默解除 pending；需要检查遗留进程。旧 Docker 活跃批次明确拒绝按 Bubblewrap 清理或重评分。
