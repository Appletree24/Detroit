## 明确收缩的范围

- 模型请求采用非流式，避免首版同时实现增量协议。断流/半个 JSON 不执行工具；流式响应状态机留后续。
- 工具串行执行；不会将未经依赖分析的调用自动并行。`apply_patch` 是带前置 digest 的唯一字面量替换，不是通用 unified diff。
- 只有完整历史策略。估算使用 UTF-8 字节数加协议余量，标记 estimator；它不是实际 tokenizer，也不用于计费。
- 只有基本有界恢复：非法参数交回模型、连续错误停止、相同调用和观测多次重复先提醒后停止。暂不重试 provider 错误；SDK `maxRetries=0`。
- shell 超时、取消或输出溢出会终止进程组，副作用状态为 unknown，后续写工具不执行。外层 Docker 回收覆盖逃逸出 shell 进程组的容器内后代。
- 运行状态精简为 running 与明确终态；尚未细分 preparing/collecting。raw stdout 为三帧 ready/accepted/done，完整证据在容器文件中采集；没有实时事件流、idle timeout 或后续用户输入协议。
- 每个 Trial 一个 Attempt，不自动重试。`recover` 清理未确认环境，不 resume 待执行 Trial；需要新批次重新实验。
- 只支持 UTF-8 常规文件；拒绝 symlink、特殊文件与二进制。单文件 1 MiB、产物总计 8 MiB、最多 2000 项。限制在采集后检查，尚无容器可写层磁盘硬配额。
- usage 缺失保留未知；未接价格表、缓存/推理 token 成本拆分、配对 bootstrap、Pi/OMP 或 Judge。

## 执行与评测边界

Agent 容器只获得初始文件、任务说明、运行 driver 和所需配置。真实 provider 请求不含 reference solution 或隐藏断言。合成变体特意使用已知解，名称、规格与报告都保留 synthetic 标识。

Agent driver provision 后降为 uid 1000；无宿主目录或 Docker socket 挂载。CPU=1、内存=512 MiB、PID=128，/tmp 有限额；脚本与 verifier 无网络，真实模型容器使用 bridge。

Verifier 为新建的只读容器。root supervisor 读取 `/control/case.json`，候选 worker 降为 uid 1000，只接收函数输入。预期输出和断言比较留在 supervisor；可见测试不参与权威评分。候选崩溃或超时属于任务 fail，supervisor 启动/协议/容器故障属于 evaluation_error。

这是面向固定、非敌对开发任务的最小评测器。它不证明候选函数没有按输入作弊，也不提供恶意多租户安全保证。driver 与 shell 共享 uid，容器内原始轨迹不构成防篡改审计；采集后的 digest 用来检测后续不一致。后续真实仓库接入需扩展产物与环境契约。

## 证据、失败与重评分

```text
.detroit/
  index.sqlite
  writer.lock                         # 仅 coordinator 存活时存在
  <experiment-id>.cancel
  attempts/<attempt-id>/
    input/                            # 初始公开工作区、构建后的 driver
    output/                           # 停止后的工作区
    evidence/events.jsonl
    evidence/objects/<sha256>         # 请求、响应、工具输出、产物对象
    artifacts.json
    verification/                     # 独立验证 staging
```

冻结的实验保存 Case 内容、seed、全部预算、完整 variant、镜像 ID、driver/verifier digest、系统提示与 Bun 版本。token 的 known sum 与 usageComplete 分开。报告成功分子要求正常结束且独立验证通过；budget/error/cancel 不由单项通过覆盖。未执行、未评分或评分器故障存在时显示 provisional。

对象先写临时文件并 fsync，再 rename，之后追加并 fsync journal。尚未实现目录 fsync、原子 manifest 发布与完整 DB/对象对账，不能宣称掉电零丢失。journal 断尾或对象 hash 错误会显式报错。

评分器代码变更后 build，再运行 `score`，会新增评分版本。相同有效评分幂等；evaluation_error 可重试并保留历史。重评分不触发 agent；费用与 usage 仍归属于原始 Attempt。

如果 verifier 回收未确认，Attempt 保留已观测的模型结果，cleanup 标为 pending，并停止继续派发。`recover` 确认 agent/verifier 都不存在后才解除清理状态。
