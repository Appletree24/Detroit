# 07 评测方法论

本文定义 Detroit 的结果口径、比较条件和报告要求。**当前 Go 实现只有 Mock 结果汇总、排除 unknown / infra_error 的成功率与 Wilson 区间；有效性阈值、配对比较、多次重复指标、Judge 校准和完整报告均为目标设计。** 实施顺序见 [路线图](08-roadmap.md)，设计约束见 [DESIGN](../DESIGN.md)。

## 1. 结果的有效性

保留已确认的主口径：成功数 S、失败数 F，N = S + F，条件成功率为 S/N。unknown 表示证据不足，infra_error 表示执行基础设施故障，两者单列、不进入 N，也不直接算模型失败。这个指标描述已有有效判定的样本，不能自动代表所有计划任务。

目标报告同时记录 planned、pending、running、terminal、cancelled、S、F、unknown、infra_error 和完成度。它们包含生命周期与评分两个维度，不可直接全部相加。每个计划位置最多选择一次执行，每份评分版本独立归类；失败重试是 Attempt，不增加计划样本数。

最终有效性要求：

- infra_error / planned ≤ 5%、unknown / planned ≤ 10%，阈值可配置并在提交时冻结。分别统计执行失败与缺证评分，防止重复归类。评分器自身故障另记 scoring_error，不冒充模型失败。
- 计划样本均已收敛，或满足事先声明的停止与报告规则；未完成运行只输出 provisional。取消、未执行和评分器故障均需说明；缺少有效性判定规则时不得默认通过。
- 必需制品、版本与 manifest 完整，必要的环境检查与标定通过。公开结果只在任务、初态、模型、动作和统计口径一致时可比较，区间重叠不构成等价证明。
- 超阈值或违反强制前提时标 invalid；保留条件成功率和诊断数据，但不得用于“已通过回归”的结论。

N = 0 时成功率未定义，不能显示成 0%。缺失可能与任务难度相关：即使未超过阈值，区间也不能抵消选择性缺失的偏差。针对固定计划，可另报缺失敏感性范围 [S/planned, (S+M)/planned]，M 为未取得有效二元判定的计划位置；它不是置信区间，也不替换主条件成功率。

## 2. 统计

### 2.1 单个成功率：Wilson 区间

对符合独立二元采样假设的 n 个结果，成功率 p̂，置信水平对应 z：

```text
center = (p̂ + z²/2n) / (1 + z²/n)
half   = z / (1 + z²/n) · sqrt(p̂(1−p̂)/n + z²/4n²)
CI     = [center − half, center + half]
```

95% 区间取 z≈1.96。报告字段应记录 method、confidence、lower、upper 与 defined，不能在置信水平可配置时仍固定命名 ci95。n=0 不计算区间。

统计单位须预先声明。同一任务的重复、同源变体和同一初态可能相关；任务加权均值也不等于简单二项比例。此时按 task / source.group_key 分层或成组估计，使用经过验证的分组方法，不能把所有 episode 当作独立任务直接套 Wilson。小样本宽区间应原样展示，不以单任务少量运行断言细微优劣。

### 2.2 两个 Subject 比较：配对设计

在相同 task、variant、init_state、seed、预算与评分规格下建立对应关系，并锁定配对清单。共同有效的独立二元样本对可用 McNemar 检验：

```text
b = A 成功、B 失败的配对数
c = A 失败、B 成功的配对数
```

根据不一致对数量选择预先约定的精确二项或适用的渐近检验，同时报告成功率差、区间、配对数和剔除原因。没有不一致对不代表已经证明等价。相关重复或来源成组时，应在组层面使用适当的配对估计方法。

同 seed 只对齐输入条件，不保证远端模型随机流相同；单侧缺失会改变共同有效子集，必须展示两侧缺失情况及敏感性分析，不能只保留“容易完成”的配对。

### 2.3 多次重复：pass@k 与 pass^k

对单题事先固定 n 次独立同分布执行，其中 c 次成功，1≤k≤n：

- pass@k = 1 − C(n−c, k) / C(n, k)，估计 k 次至少一次成功的概率。
- pass^k = C(c, k) / C(n, k)，估计 k 次全部成功的概率。

两者分别反映多次尝试机会和重复可靠性；跨题按预先固定的权重汇总。基础设施重试不增加 n，多份评分不增加 n。发生 unknown、infra_error、结果相关的提前停止或补跑时，不能删除这些位置并缩小 n 后继续宣称对原计划无偏；应报告不适用原因，或按固定计划另行给出缺失敏感性范围。

### 2.4 样本量规划与停止

样本量规划以目标差异、基线水平、功效、显著性、配对结构和组内相关性为输入；估算值必须注明假设。重复观察结果后决定停止，需要专门的顺序方法，不能继续沿用固定样本检验的结论。当前 CLI 不提供样本量规划命令。

### 2.5 多重比较与成本

比较多个扰动轴、suite 或 Subject 时，预先声明检验族，必要时使用 Holm 等校正，展示原始与校正后结果及效应大小。探索性分析与事先指定的回归门槛分开展示。

成本覆盖所有 Attempt、超时但可能已执行的请求、重复远端调用和 Judge 评分。记录已知、估计、未知三类用量与冻结的价格版本；不能只累计最终被选中执行的费用。吞吐同时给出工作量、并发、硬件与完成度。

## 3. Judge 校准

LLM / VLM Judge 是需要验证的评分组件，不能把模型生成的解释直接当成人工真值或根因。

1. 建立与实际任务分布相符的人工标注集，覆盖成功、失败、未知和关键少数标签；记录标注者分歧与裁决过程。样本量按标签覆盖和所需精度确定。
2. 使用独立验证集评估一致率、分标签混淆矩阵、精确率 / 召回率及适用的 Cohen's κ；类别不平衡时同时解释 κ 的局限。阈值由用途事先确定，不把单一通用分数当作充分保证。
3. 检查成对顺序、回答长度和模型同源偏差；检查依据是否真实存在于制品中。缺少必要输入返回 unknown 或 scoring_error，不补造证据。
4. 固定模型版本、提示词、输入采样、解析器、taxonomy 与评分环境。不同版本不混合汇总；随机 Judge 重复评分保留独立记录。
5. 校准、改进和独立验证用途分开。材料一旦参与提示词调优，其历史仍可追踪，但不能继续宣称为未暴露验证材料。

规则判定与 Judge 分析分别保存。规则可判成功时，附加诊断 Judge 故障不自动推翻该成功；若 Judge 是必要评分依赖，则按已冻结的组合规则处理。

## 4. 失败归因

### 4.1 打标

Agent 与具身 taxonomy 见 [05](05-vertical-agent.md) 和 [06](06-vertical-embodied.md) 的 §6。一个失败可含多个标签，primary 仅用于一种固定的聚合口径。每条标签关联轨迹、动作、工具返回或视频帧等证据，并记录规则 / Judge / 人工来源。

### 4.2 聚类与复核

可对解释文本与结构化错误聚类，由人工检查代表样本后决定是否扩充 taxonomy。聚类是发现线索，不能代替真实错误验证，也不能用新标签覆盖历史记录。

### 4.3 影响排序

按 primary 标签计数除以已声明的分母，展示该类失败的频率与基线变化。这个比例表示受影响样本占比，不等于修复后的成功率提升，更不证明某次改动引入了该问题。因果结论需要受控复现或干预验证。

## 5. 可复现性

### 5.1 Manifest 与制品

当前代码的 manifest 记录 spec / taskset 摘要及版本等基础元数据，尚不构成完整的运行快照。目标 manifest 至少固定：

| 类别 | 必须记录 |
| --- | --- |
| 输入 | 原始包、task、初态、材料及来源组摘要，loader 版本和转换损失 |
| 执行 | run_id、plan_digest、Episode / Attempt 身份、预算、重试与停止政策 |
| Subject | 适配器、模型 / checkpoint、请求配置与可观测的实际配置 |
| 环境 | 镜像内容摘要、benchmark 版本、动作与观测 schema、硬件 / 驱动 |
| 评分 | scoring_digest、评分器 / Judge / 提示词版本、输入证据摘要 |
| 采样 | seeds、repeats、扰动、配对与分组方法 |
| 制品 | 字节摘要、大小、格式、路径语义、截断与完整度、采集错误 |
| 报告 | 统计方法、置信水平、有效性阈值、选择规则与价格版本 |

Worker 只能读取冻结输入；内容寻址不能证明语义正确或来源可靠。重评分读取现有证据并新增 Evaluation，不重跑 Subject；依赖未保存在线终态的评分须明确不可重评。重新执行生成新实验身份，不能把传输重试、续跑、重评与新实验混为一谈。当前 CLI 尚无 replay / rescore 命令。

### 5.2 已知非确定性

GPU 浮点、批大小、模型服务内部采样、模拟用户、实时工具与环境版本都可能影响输出。记录已知条件、无法观测项与同配置重跑的差异。种子和哈希帮助追踪条件，不能承诺结果位级复现。

### 5.3 环境检查与标定

| 检查 | 目的 |
| --- | --- |
| 观测朝向与 schema | 确认相机方向、尺寸、归一化及字段匹配 |
| 动作语义 | 确认坐标系、单位、夹爪约定、频率与动作块边界 |
| 零动作 / 脚本基线 | 对有相应预期的任务检查成功谓词与环境推进，不能对所有任务机械要求 0% / 100% |
| 上游同条件对照 | 对齐 checkpoint、任务、初态与统计口径，解释差异后确认标定 |

具身标定和真实 Subject 检查均为待实现能力。

## 6. 报告规范

目标每份报告包含：

1. 结论摘要：适用范围、效应大小、不确定性及 provisional / valid / invalid 状态。
2. 有效性检查：完整计划分母、完成度、infra_error、unknown、scoring_error、取消、环境检查与标定。
3. 分组成功率表：N、评分版本、置信方法与水平；不能计算区间时给原因。
4. 与基线的配对比较：配对覆盖率、单侧缺失、采样假设和校正策略。
5. 失败频率与证据链接，区分候选归因与已验证根因。
6. 吞吐与成本：覆盖所有尝试、评分开销和未知用量。
7. 输入完整度：按 task.tools.source 和 task.system.status（10 §6.2）分组，标明近似或缺失输入。
8. Manifest 摘要、制品完整度与报告规格。

成功率必须有分母和不确定性说明；条件不满足时明确不可估计，不生成形式上存在但不适用的 CI。当前 JSON 汇总不代表已经具备上述完整分析能力。
