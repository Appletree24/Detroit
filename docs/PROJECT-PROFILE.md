# Detroit 项目介绍

以下按项目完整目标形态撰写；当前已实现范围见 [README](../README.md)，实施顺序见 [路线图](08-roadmap.md)。

**Detroit｜统一智能体评测平台（LLM Agent + 具身策略）**

面向模型选型、Agent 迭代与机器人策略验证，构建覆盖评测集导入、分布式执行、独立评分、统计比较和回归管理的平台。通过统一任务与交互协议连接工具调用 Agent 和视觉语言动作策略，使不同环境下的评测共享可靠调度、证据追溯和分析能力。

**技术栈：** Go、Python、gRPC / Protobuf、SQLite / PostgreSQL、Docker、MuJoCo / LIBERO、对象存储、Prometheus。

- **统一协议：** 设计 Task / Env / Subject / Episode 抽象及版本化评测集协议，解耦环境、被测对象与评分器；冻结任务内容、材料、初态、环境和模型配置，通过能力预检与适配器接入自定义任务、公开 benchmark 和策略服务。
- **可靠调度：** 基于 Go 实现拉式分布式调度，通过租约心跳、attempt fencing、幂等提交与持久化恢复处理崩溃、断网和迟到上报；区分基础设施重试与独立采样，结合资源准入、多环境并行及 GPU 批量推理控制执行成本。
- **双垂类执行：** 为 Agent 构建 Docker 沙箱、工具交互、终态导出与资源治理；以 Python 接入 MuJoCo / LIBERO、LeRobot 和 VLA 策略，完成观测动作协议校验、基线标定及相机、布局、语言扰动评测，两类 Worker 复用同一内核。
- **统计与归因：** 以 Wilson 区间、配对检验及 pass@k / pass^k 评估能力与稳定性，显式处理缺失、相关采样和无效运行；结合规则、LLM / VLM Judge 与人工复核定位失败，通过一致性指标、混淆矩阵和偏差检查校准裁判。
- **追溯与回归：** 用不可变 manifest、内容摘要和版本化制品关联配置、轨迹、产物及评分依据；支持独立重评分、失败归因报告与 CI 回归门禁，固定基线及统计口径，实现从异常结果到证据、再到版本验证的完整闭环。

任务规模、吞吐、成本和效果指标仅在取得真实实验依据后补充；本介绍不预设性能提升或已支持的具体 benchmark 版本。
