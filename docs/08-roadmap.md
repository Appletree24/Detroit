# 08 路线图

Detroit 的目标是 **Go 控制面 + Worker / Subject 服务协议的统一智能体评测平台**，覆盖 LLM Agent 与具身策略两个垂类。本路线图依据 [范围共识](../CONTEXT.md)、[系统架构](02-architecture.md) 和 [设计优化](../DESIGN.md)，按依赖安排实施顺序，不承诺日期。以下验收条件是目标，不代表能力已经实现。

## 当前实现基线

| 模块 | 已有实现 | 尚未完成的边界 |
|---|---|---|
| 核心类型与 RunSpec 解析 | 03 中的类型全部落地，有单测 | ✅ `internal/core` |
| v2 评测集导入 + TaskSet Loader | JSON/JSONL/bundle 校验、冻结快照、独立评分绑定；导入后可提交、续跑 | ✅ `internal/dataset`、`internal/taskset`；CLI 端到端测试使用 mock Worker |
| SQLite 元数据存储 + 本地制品存储 | episode upsert 幂等；kill -9 后重启续跑不重复、不丢失 | 元数据 ✅（`test/e2e` 验证 kill -9）；模型单步制品与路径查询 ✅，完整制品后端待做 |
| 调度器（租约 + 心跳 + 重试） | 模拟 Worker 随机崩溃，所有 episode 最终完成或进入 infra_error | ✅ `internal/scheduler` |
| `openai-compatible` Subject 适配器 | 能驱动一个工具调用 Agent 完成多步任务 | 单步 Chat Completions + Subject gRPC ✅；多步待做 |
| Docker 沙箱 Worker（L1） | 从快照启动、导出终态、销毁；资源超限可判定 | 沙箱 ✅（`workers/agent/sandbox`，真实 Docker 集成测试）；接入 Worker 待做 |
| 确定性 Scorer + Wilson 区间 + Markdown 报告 | 报告中每个成功率都有 N 与 CI | Wilson 区间 ✅；next_message 确定性 Scorer 和本地请求/响应/评分制品 ✅；环境 Scorer、Markdown 报告待做 |
| 一个 smoke 任务集（≥20 个任务） | 两个不同模型的端到端对比报告 | 待做（目前只有 synthetic 占位任务） |

目前可运行的是 `提交 RunSpec → synthetic 任务 → Mock Worker → 结果入库 → CLI 统计`。Docker 沙箱是独立模块，尚未接入上述执行链。代码中存在测试不等于当前环境已通过全部测试；Docker 集成测试在依赖不可用时会跳过。Mock 结果不能当作真实模型或策略成绩。

## P0：固定执行身份，补齐恢复与统计契约

| 交付 | 验收条件 |
|---|---|
| 不可变任务与执行计划 | 提交时固定任务内容、初态、变体参数、材料、环境、Subject 配置和适配器版本；Worker 按摘要取回同一份内容。修改来源内容生成新身份，不复用旧结果 |
| episode 与 attempt 分层 | episode 表示计划中的样本，attempt 表示某次租约下的执行，基础设施重试产生新 attempt；每次租出携带 fencing token。旧 Worker 的迟到上报不能覆盖当前尝试，也不能把重试算成额外独立样本 |
| 执行到提交的可靠生命周期 | 覆盖 `running → reporting → acked`；结果在 ACK 前可恢复，提交期间不提前失去租约保护。租约失效后停止执行；重复报告幂等，冲突报告可诊断 |
| 评分与报告身份 | 执行结果、评分记录、归因标签分别版本化；更新评分不重写执行。固定成功率分母、配对键、重试归属和报告所引用的评分版本 |
| 运行有效性与缺失表达 | `unknown`、`infra_error`、未完成、取消和评分故障分别保留；当前统计具备 `unknown` / `infra_error` 的排除与计数，尚无阈值门禁。默认 `unknown > 10%`、`infra_error > 5%` 的有效性门槛是待实现目标，阈值及分母随报告冻结 |

验收增加网络分区、报告 ACK 丢失、旧 attempt 迟到、控制面与 Worker 重启、取消和上报竞争等场景。保证结果提交和统计不重复；不承诺任务物理执行恰好一次，也不把同一 seed 等同于相同模型输出。

## P1：v2 导入与真实 Agent 闭环

| 交付 | 验收条件 |
|---|---|
| v2 导入与预检 | 实现 [评测集协议](10-dataset-format.md) 的题目、评分、集合与材料导入；检查摘要、来源、输入可见性、环境要求和评分兼容性。可保存不完整材料，但缺少执行必要条件时阻止运行 |
| `next_message` 对话 Worker | 通过 `openai-compatible` Subject 产生下一条回复；工具调用只记录、不执行，保留实际请求、输出及可观测用量 |
| Docker Agent Worker | 串起环境恢复、Subject 多步交互、工具执行、在线确定性评分、终态导出和销毁；资源限制注明硬限制、监测限制或不可观测，清理失败可重试 |
| 不可变制品 | 本地 ArtifactStore 保存清单、轨迹、工作区终态和评分证据；记录摘要、大小、权限及截断 / 缺失状态，按 attempt 隔离并原子提交 |
| 真实对比与重评分 | 固定任务、环境、Harness 和评分，完成两模型真实运行；基于已有证据追加新评分版本，不调用被测对象、不覆盖旧记录 |

验收产物是一组来源可说明、具备可靠判分依据的任务，以及可核对配置、轨迹、产物和评分的实验报告。用已知正负样例检查评分器；与真实模型成绩分开。不以获得正向提升为交付条件。随后通过限定版本的 Terminal-Bench、SWE 系列等适配验证异构任务；导入兼容、执行兼容和评分口径分别验收。

## P2：评分、Judge 校准、报告与回归

| 交付 | 验收条件 |
|---|---|
| 版本化评分体系 | 在线评分访问环境终态，离线评分复用制品；保留必过条件、多维分项、证据与未知原因，使用 `scorers.select` 选择版本明确的评分组合 |
| LLM Judge 与人工校准 | 记录模型、提示词、解析逻辑和标签体系版本；人工标注集报告 Cohen's κ、混淆矩阵及位置 / 冗长 / 同源偏差，低可信标签明确标注 |
| 统计比较 | 实现满足适用条件的同题配对检验、pass@k / pass^k、样本量规划和多重比较校正；处理同题重复的相关性与缺失配对，明确推断单位，不强求显著差异 |
| 失败归因与报告 | 规则 → Judge → 人工复核形成证据可追溯的归因链；输出版本化 Markdown / HTML 报告，展示样本量、区间、有效性检查、分组失败与成本 |
| CI 回归门禁 | `detroit gate` 根据冻结阈值区分通过、回归、证据不足和运行故障；保存基线版本及完整报告，未知或无效运行不能静默通过 |

Judge 校准和统计结论必须有实测依据。样本量、κ、回归阈值等先作为实验配置，不能将设计门槛写成已达到的质量或性能指标。

## P3：具身垂类与共享内核验证

| 交付 | 验收条件 |
|---|---|
| Python 具身 Worker | 接入 MuJoCo / LIBERO，并通过适配器使用 LeRobot 生态；与 Agent 复用 episode 调度、制品、评分版本及报告，环境依赖留在 Worker |
| VLA Subject | 接入 SmolVLA / openpi 等具体版本；验证相机、图像处理、状态与动作语义、动作块长度和 session 隔离，执行 Describe / Reset / Act 协议契约测试 |
| 标定与鲁棒性扰动 | 固定模型权重、环境、初态和评测口径，先对齐可信基线；公开成绩仅在条件可比较时作为参照。对 camera / layout / language 等扰动分别记录版本和配对结果 |
| 子目标与 VLM 归因 | 用子目标谓词提供规则证据，视频及关键帧支持 VLM Judge；复用人工校准与归因体系，记录标注一致性和失败案例 |

验收交付完整的基线标定记录和扰动实验，说明不一致的环境或指标条件。仿真结论限定于已验证条件；仿真与真机相关性属于后续实证，不能由仿真成绩推断。

## P4：多 Worker、GPU 推理与部署验证

| 交付 | 验收条件 |
|---|---|
| 能力匹配和资源准入 | 按垂类、执行模式、镜像 / 运行时、GPU 与显存等能力分配任务；无合适 Worker 时给出原因，控制并行数与预算 |
| 多环境与批量推理 | 实现 Subject ActBatch、session 隔离、超时和单项错误处理；实测并行度、吞吐、延迟、GPU 用量与瓶颈，不预设提升幅度 |
| 存储与多机部署 | 从 SQLite + 本地制品扩展到 PostgreSQL + 对象存储；验证数据库并发、制品完整提交、Worker 重启及断网恢复，明确受支持的控制面拓扑 |
| 运维与交付 | 提供单机部署、远端 Worker 接入、身份鉴别与传输配置、Prometheus 指标及排障说明；所有对外数字链接到带 manifest 的 run |

## 范围与推进原则

优先完成身份与恢复正确性、真实 Agent 闭环、评分可信性，再进入具身标定和多机验证。保留双垂类与多机的总体方向，通过可独立验收的阶段控制范围。gVisor、额外 benchmark、更多扰动轴、失败聚类和仿真到真机实验可按资源后置；任务冻结、租约隔离、完整证据、统计适用条件和基线标定不可省略。

评测数据生产继续由外部插件或数据集提供方完成；不以恢复旧 TS/Bun 实现、OMP 原生采集或增加 Web 界面为前提。阶段完成以可审阅的代码、实测记录和报告判断，简历介绍中的目标能力不作为当前完成度证明。
