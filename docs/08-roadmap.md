# 08 路线图

起始日期：2026-10-12。顺序原则：**先内核 + Agent 垂类（主线），再具身垂类（差异化）**；每个里程碑结束时都有一个可演示、可写进简历的成果。

## M1 内核 + Agent MVP（10/12 – 10/25）

| 交付 | 验收标准 |
|---|---|
| 核心类型与 RunSpec 解析 | 03 中的类型全部落地，有单测 |
| SQLite 元数据存储 + 本地制品存储 | episode upsert 幂等；kill -9 后重启续跑不重复、不丢失 |
| 调度器（租约 + 心跳 + 重试） | 模拟 Worker 随机崩溃，所有 episode 最终完成或进入 infra_error |
| `openai-compatible` Subject 适配器 | 能驱动一个工具调用 Agent 完成多步任务 |
| Docker 沙箱 Worker（L1） | 从快照启动、导出终态、销毁；资源超限可判定 |
| 确定性 Scorer + Wilson 区间 + Markdown 报告 | 报告中每个成功率都有 N 与 CI |
| 一个 smoke 任务集（≥20 个任务） | 两个不同模型的端到端对比报告 |

## M2 Agent 垂类完整化（10/26 – 11/01）

| 交付 | 验收标准 |
|---|---|
| 工具录制 / 回放 + 故障注入 Variant | replay 模式下同配置两次 run 结果一致（温度为 0 时） |
| 垂直领域评测集构建器 | 选一个具体业务领域（如电商售后），从 ≤10 个种子样例生成 ≥100 个经可解性校验的任务 |
| LLM Judge + taxonomy + 人工标注集 | Judge 与人工 κ 有实测值并写入报告 |
| McNemar 配对比较 + pass^k | 两个模型 / 两版 harness 的对比报告含显著性结论 |
| 回归门禁 CLI | `detroit gate` 返回非零退出码可接入 CI |

## M3 具身垂类（11/02 – 11/15）

| 交付 | 验收标准 |
|---|---|
| LIBERO Worker（基于 LeRobot gym 封装） | 零动作基线 ≈ 0；朝向检查通过 |
| SmolVLA 适配器（联调） | 单 suite 端到端跑通 |
| openpi 适配器 + pi0.5 标定 | 四个 suite 复现值落在公开值的置信区间内；`calibration-log.md` 记录排查过程 |
| 扰动 Variant（至少 camera / layout / language 三轴） | 扰动结果按轴分组，附配对比较 |
| 子目标谓词 + 规则层失败归因 | 每个失败 episode 有 primary 标签 |
| VLM Judge（复用 Agent 垂类的 analyze 代码） | 与人工抽样的一致性有实测值 |

## M4 规模化与打磨（11/16 – 11/22）

| 交付 | 验收标准 |
|---|---|
| 多环境并行 + 批量推理 | 吞吐报告：不同并行度下的 env_steps/sec 与瓶颈分析 |
| Prometheus 指标 | 调度状态可观测 |
| 两篇技术博客 | ① Agent 垂类：自定义评测集与 Judge 校准；② 具身垂类：LIBERO 复现与扰动下的失败分析 |
| README 中的结果区 | 所有数字链接到带 manifest 的 run |

## 砍需求顺序（时间不够时从上往下砍）

1. 多机部署（Postgres / MinIO）——单机足以演示
2. gVisor（L2 沙箱）
3. 失败聚类（4.2）——保留打标与影响排序
4. 仿真-真机相关性模块——只保留方法论文档
5. 第三个以上的扰动轴
6. Prometheus 指标

**不能砍**：幂等与续跑、Wilson 区间、配对检验、manifest、标定、失败归因的规则层。这些是项目区别于"跑脚本出分数"的核心。

## 风险

| 风险 | 应对 |
|---|---|
| pi0.5 标定对不上 | 预留 3 天排查；先用 LeRobot 官方评测脚本跑出参照值，再对比 Detroit 的结果，二分定位差异 |
| GPU 资源 | 开发用 SmolVLA；全量评测按小时租用云 GPU，集中在 M3 后半段 |
| 时间被面试挤占 | 每个里程碑独立可展示；M2 结束即具备完整的 Agent 评测故事 |
