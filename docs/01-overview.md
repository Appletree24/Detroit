# 01 定位与目标

## 1. 问题定义

评测是模型迭代的"北极星"：每一个训练 checkpoint、每一次 prompt / harness 改动，都需要回答三个问题：

1. **它变好了吗？**（结论是否统计显著）
2. **这个结论能复现吗？**（换机器、换时间再跑一次还成立吗）
3. **如果变差了，差在哪？**（哪类失败变多了，影响多大）

现实中，这三个问题经常被一个"成功率 xx%"草草带过。Detroit 要让这三个问题的答案成为评测流程的默认产出。

## 2. 为什么 LLM Agent 和具身策略可以共用一套内核

| 概念 | LLM Agent 评测 | 具身策略评测 | 统一抽象 |
|---|---|---|---|
| 环境 | 沙箱容器（文件系统、shell、模拟 API、模拟用户） | 物理仿真器（MuJoCo / ManiSkill / Isaac） | `Env` |
| 观测 | 对话历史 + 工具返回 | 多视角图像 + 本体状态 + 语言指令 | `Observation` |
| 动作 | 文本回复 / 工具调用 | 末端位姿或关节动作块（action chunk） | `Action` |
| 被测对象 | LLM + harness | VLA / 策略网络 | `Subject` |
| 一次完整尝试 | 一次任务会话 | 一条 rollout | `Episode` |
| 成功判定 | 终态检查、单测、rubric | 仿真器状态谓词、子目标 | `Scorer` |
| 失败归因 | 工具选错、死循环、越权操作 | 抓错物体、空抓、卡住不恢复 | `Analyzer` |

差异只存在于 `Env`、`Subject` 适配器和领域相关的 `Scorer`；调度、存储、统计、归因、报告全部共享。

## 3. 目标

- **G1 统一内核**：新增一个垂类只需实现 Env worker、Subject 适配器和 Scorer，不改核心代码。
- **G2 可扩展执行**：episode 级并行，单机多进程到多机横向扩展；任意时刻中断都能续跑。
- **G3 统计严谨**：所有成功率附带 95% 置信区间；模型对比使用配对检验；提供样本量规划。
- **G4 可复现**：每次 run 产出一份运行清单（manifest），据此可以重放出相同配置的 run。
- **G5 失败可解释**：每个失败 episode 有结构化的失败标签，报告中按影响排序。
- **G6 垂直领域可定制**（Agent 垂类）：用户能用少量样例为自己的业务领域构建评测集。

## 4. 非目标

- 不提出新的公开 benchmark，不做排行榜。
- 不自研物理仿真器或渲染器，具身垂类直接集成 LIBERO / LeRobot 等现有环境。
- 不做模型训练；只消费 checkpoint。
- 不做真机评测调度（保留接口，不在路线图内）。

## 5. 与现有工具的关系

Detroit 刻意"自建内核、集成环境"：调度、存储、统计、归因、报告自己写，因为这是评测平台的核心价值，也是工程能力的体现；仿真器和 benchmark 任务直接复用社区实现，因为重写它们既没有价值也无法保证与公开结果对齐。

| 工具 | 关系 |
|---|---|
| LeRobot `lerobot-eval` | 具身垂类的环境来源之一（LIBERO 等通过其 gym 接口接入）；Detroit 在其之上提供分布式调度、统计和归因 |
| LIBERO / LIBERO-Plus / LIBERO-PRO | 具身垂类的首批任务集与扰动集 |
| openpi | pi0 / pi0.5 等策略的推理服务，作为 Subject 接入 |
| SimplerEnv、RoboArena、PolaRiS | 仿真-真机相关性方法论的参考（见 06、07） |
| Isaac Lab-Arena、RoboLab | 后续可选的环境后端；需要 RTX 显卡，不在首期范围 |
| τ-bench、Terminal-Bench 类 benchmark | Agent 垂类的任务形态参考（模拟用户 + 终态检查；终端沙箱 + 测试判定） |

## 6. 成功标准（项目层面）

1. 在 Agent 垂类上：一个自建的垂直领域评测集 + 一个公开任务形态的复现，产出带置信区间和失败归因的对比报告。
2. 在具身垂类上：复现一个公开 VLA checkpoint 在 LIBERO 上的成绩，误差在置信区间内；在扰动集上给出性能下降与失败分布。
3. 两个垂类的报告由同一套 `stats / analyze / report` 代码生成。
